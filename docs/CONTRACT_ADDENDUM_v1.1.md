# 州提名应用 · v1.1 契约修订附录

本附录独立补充原始说明书，保留原文件。它明确参考原型采用的契约及后续扩展边界；不宣称原说明书所有 P0 项目已完成。

## 指标必须分开

| 指标键 | 含义 | 计算与展示约束 |
|---|---|---|
| `nomination_allocation` | 年度州提名配额 | 与州提名邀请、已完成提名、签证邀请和获签分别处理 |
| `nomination_invitation_count` | 州提名邀请记录数 | 原型使用合成记录；不得表示实际获签人数 |
| `visa_invitation_count` | 签证邀请记录数 | 与州邀请分开；分布还需明确群体和分母 |
| `eoi_stock_count` | 指定时点 EOI 池存量 | 库存不按年度流量累加，也不等于独立申请人数 |
| `last_invited_eoi_points` | 来源公布的末位获邀 EOI 分数 | 不作保证门槛、个人概率或完整分布 |

原型没有实现“已完成提名”和“获签”两类事实。这两类需独立新指标与证据。

`value` 缺失必须是 `null`，并有 `status` 与 `nullReason`。仅真正观测到零时允许 `available + 0`。隐去值不得用总数或已公布分组倒推。

## 发布版本与证据固定

每个事实拥有 `canonical_key + revision`。`dataset_observation` 固定一个发布版本引用哪些事实修订；`dataset_source` 固定该版本的证据快照。查询必须通过这些成员表读取。

发布后，事实、成员、证据、范围、已引用职业定义和分布都冻结；修订新增事实和新发布版本。`demo-v1` 的软件工程师邀请数是 35，`demo-v2` 是 40，旧版保持 35。发布审计采用追加事件。已发布版本可撤回，撤回后不重新发布。

事实键涉及可空字段时使用 PostgreSQL `UNIQUE NULLS NOT DISTINCT`。参考版本用相同规则阻止没有职业、日期或时点的重复配额。

Demo 和 verified_historical 分别筛选发布版本，事实模式和来源模式相符；跨模式版本或来源访问返回 404，不回退到其他版本。

## 可比较职业排名

排名的比较组包含州、州提名签证、年度、轮次、通道、居住类别、分数口径、分类版本。先选择来源提供的范围，再计算。

末位分数从低到高，州提名邀请数从高到低；PostgreSQL `DENSE_RANK()` 保留并列名次，职业代码作为稳定排序。展示最多五项，另带有效记录数与边界并列组大小。有三条证据就展示三条，不补零、不补职业。

当前样本每个选定轮次只有一种分数口径和分类版本；存在多个口径时返回 409。未来需要把这两项也作为显式可选择筛选字段，再允许发布多口径数据。

## 分布和年度

分布返回群体类型、分母、分母定义、分组、状态与 `chartAllowed`。只在群体适用、分母为正、分组完整、互不重叠且计数总和匹配分母时计算 SQL 百分比并绘图。其他情况保留表格和缺失原因。末位分数群体不构成分布。

年度趋势只接受邀请流量指标。必须有起止日期、相同统计口径和不重叠的期间；PostgreSQL 求和。未覆盖完整项目年度的期间标为 YTD，单独展示，不与完整年度同比。

参考界面的分布和趋势是条形图及数据表。没有完成原说明书可能要求的全部图形变体。

## 来源和时间

每份来源保留机构、原 URL、来源 ID、证据版本 ID、SHA-256、许可、保留范围、检索时间、发布时间和生效日期。每条观测保留行或字段定位。发布时间不明确时是 null，不能用检索日期填充。

真实样本的哈希覆盖原始 HTML 表片段，不声称保留了整份网页。`round_id` 指向这份合成来源所定义的轮次；`event_date` 为轮次观测日期；`eoi_effective_at` 表示来源说明的 EOI 生效时点，两者不能互换。真实轮次录入前需审查这些字段的来源含义。

## API 与问答

GET 查询的共同筛选为 `mode`、`programYear`、`visaSubclass`、`sponsorshipType`、`locale` 和可选的 `datasetVersion`。排名另含 `roundId`、`stream`、`residenceCategory`、`metricType`、`limit`。客户端缓存完整 URL，包括模式、年度、版本和比较范围。

响应统一为 `{data, meta, sources, warnings}`。错误返回 ProblemDetails、稳定 `code` 与 `traceId`；覆盖 400、404、409、422、429、503。没有 SQL、任意 URL、写入或个人资料接口。

提问先经 `/api/query/interpret` 识别候选和缺项。用户确认职业代码、分类版本和查询条件后才调用 `/api/answers`。模板只陈述查询事实及局限；没有密钥也能工作。未来的 Gemini 只允许辅助理解和表述，数值仍须由 SQL 给出。
