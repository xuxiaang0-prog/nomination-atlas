# 和 Codex 从空项目复建

参考应用是目标样品。我们从独立空目录重建，每一阶段都要能解释数据含义、展示运行结果，并通过对应验收，再进入下一阶段。

## 阶段交付

| 阶段 | 你完成的成果 | 通过标准 |
|---|---|---|
| 0. 环境 | Node、.NET、PostgreSQL 运行记录与空项目 | 能说明浏览器、API、数据库各自负责什么；健康检查可读 |
| 1. 第一条数据链路 | 8 州目录、配额表、`GET /api/states`、简单列表 | 配额来源可追溯；没有数据显示缺失；190 和 491 不合并 |
| 2. React 地图 | 八州 SVG、文本列表、州详情路由 | 鼠标/键盘均可选州；ACT 可选；手机和 200% 缩放可用 |
| 3. 模式与来源 | Demo/真实模式、来源弹窗、完整缓存键 | 模式切换不残留旧数值；发布时间未知仍为空 |
| 4. SQL 排名 | 范围确认、两类 Top5、并列与缺失 | 同组比较；最多五条；三条不补足；隐去值不变成零 |
| 5. 职业详情 | 名称/别名/代码搜索、确认分类版本、观测表 | “工程师”有多个候选；必须确认具体代码 |
| 6. 分布与趋势 | 分母约束、缺失表格、年度 SQL 总量、YTD | 未知/隐去分组不显示占比；库存不被当年度流量累加 |
| 7. 版本化 | 不可变发布、事实修订、固定证据成员 | 新版为 40 时旧版仍是 35；公开读者写入被拒绝 |
| 8. 模板问答 | 识别→确认→查询→回答 | 没有模型密钥也可用；不输出个人获邀概率 |
| 9. 官方历史 | 多粒度历史表、哈希校验、只读档案与覆盖说明 | WA 不虚构职业人数或签证拆分；ACT / TAS 分数不变成 EOI；SA 组人数不归到具体职业 |
| 10. 验收与复盘 | 契约测试、实际浏览器验证、覆盖矩阵 | 每条“完成”都有证据；未执行项标为待验收 |

## 第一节具体怎么做

先记录你的操作系统、编辑器以及以下命令输出：

```bash
node --version
npm --version
dotnet --version
docker --version
```

随后我们建立一个新的空目录。第一节只完成 `GET /health/live`、八州目录和一个 React 州列表。你自己创建项目、解释请求如何进入 API、如何返回数据。我审查命名、路由、空值处理，并给出下一步改动。

第一节结束时，应能回答：

1. 为什么配额不能叫“已经获邀人数”？
2. 数据未公布与真实值为零，在 API 和界面分别怎样表示？
3. 前端为什么不能凭一个末位分数画完整分布？

## 合作方式

每次只做一个可运行的纵向功能。你先实现并说明选择，我检查行为、边界和证据，必要时给小范围示例。我们保留过程中的失败案例，直到你能独立定位问题并复验。

每节产出是运行截图或浏览器演示、代码差异、验收结果，以及一段用自己的话写的解释。参考源码用于对照。最终以你的独立复建版本能通过相同检查为准。

## 先审查参考版

体验后把发现按三类记录：行为不符合预期、信息难以理解、视觉/操作不符合标准。每项写下具体页面、操作、实际结果和期待结果。

参考版尚未执行实际浏览器视觉验收与原生 PostgreSQL / Docker 验收；这些可以成为我们共同复建时的明确验收任务。v0.2 已接入四个州及领地的部分官方邀请历史；复建时先选一种数据口径完成纵向功能，再扩展到职业组、通道合计和不同分数体系。全国完整历史、实时更新和政策资格引擎不在本版范围。
